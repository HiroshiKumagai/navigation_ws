# 開発ロードマップ

Sep 25, 2026 作成

[locomotion_spec.md](locomotion_spec.md) の機能を、シミュレーション上で段階的に実装するための計画。
各ステップの最後に「シミュレーションで確認できること」を置き、仕様とコードを並行して直しながら進める（仕様書 9 章）。

## 方針

- ミッションサーバは **Python**（rclpy + grpcio）で実装する
- UI はまず **PySide6 のローカルアプリ**として作り、最終的にブラウザへ移す。UI は gRPC API のクライアントに徹し、ROS 2 には直接触れない（ブラウザ版に移すとき、差し替えるのは画面だけにする）
- 異常の再現（安全停止・機器異常・ワープ）は、製品の UI とは別の**テストパネル**で行う
- ミッションサーバから見た ROS 2 の接点は、シミュレーションと実機で同じにする（仕様書 9 章）

## ステップ 1: ミッションサーバの骨格（移動と状態管理）

サーバを「状態管理の中核」「ROS 2 アダプタ」「gRPC サービス」の 3 層に分ける。中核は ROS 2 にも gRPC にも依存させない。

- [ ] **1-1 proto の配置とコード生成**: `doc/locomotion.proto` を `proto/locomotion/v1/` へ移し、Python コードを生成する仕組みを作る（`grpcio-tools` を `.venv` に追加）
- [ ] **1-2 状態遷移の中核**: 仕様書 4 章の遷移表をデータとして持ち、受理・拒否（FAILED_PRECONDITION）の判定とタスクの結果（成功・中断・失敗）を決める。**遷移表の各行を単体テストにする**
- [ ] **1-3 ROS 2 アダプタ**:
  - Nav2: `NavigateToPose` / `NavigateThroughPoses` の送信・キャンセル、フィードバック（リカバリ回数 → 回避動作中）
  - AMCL: 推定位置と共分散（自己位置の良否判定）、初期位置の設定
  - 安全系: `/safety/state` の購読、`/safety/reset` の送信
  - 指令切替ノード: モードの切り替え
- [ ] **1-4 地点の保存（最小）**: 1 枚の地図の中の地点 ID と姿勢を保存する
- [ ] **1-5 gRPC サービス**: `RobotService`（GetStatus / WatchStatus / WatchPose / SetMode / SetInitialPose / ResetSafetyStop）と `TaskService`（StartTask / PauseTask / ResumeTask / StopTask / RetryTask / GetTask / ListTasks）。地点の登録は `PointService` の最小限（CreatePoint / ListPoints）
- [ ] **1-6 確認用のコマンドラインクライアント**

**確認できること**
- コマンドラインから地点 ID を指定して移動し、一時停止・再開・停止ができる
- テストパネルで保護停止をかけると「移動中 → 安全停止」、解除すると「一時停止」へ遷移し、再開で移動が続く
- 状態が許さない操作は FAILED_PRECONDITION で拒否される

## ステップ 2: ローカル UI（運用画面）

- [ ] **2-1 画面の構成を決める**: 画面一覧・遷移・主要画面のワイヤーフレーム（仕様書 10 章の未決事項）
- [ ] **2-2 運用画面（④ 監視・指示）**: 地図上のロボットの位置と状態、UI 指示モードでの移動指示、停止・一時停止・再開、モード切替
- [ ] **2-3 保守画面（⑤ 異常時の復旧）**: 異常の分類の表示と、分類ごとの復旧操作（再試行、初期位置の再設定、手動操作への切替）

**確認できること**
- UI だけで、移動指示から異常の復旧まで操作できる

## ステップ 3: 異常の分類と復旧（仕様書 5 章）

- [ ] **3-1 分類の判定**: 経路閉塞・目標到達不能（Nav2 の結果とエラーコード）、自己位置喪失（AMCL の共分散としきい値）、機器異常（各ノード・トピックの死活監視）
- [ ] **3-2 異常を起こす手順**: 4 つの分類をそれぞれ意図的に起こす手順を用意する（障害物の配置、目標を障害物の上に置く、ワープ、機器の停止）
- [ ] **3-3 結合試験の自動化**: 遷移表の全行を、シミュレーション上の試験として自動で回す

**確認できること**
- 4 つの異常がそれぞれ正しく分類され、UI から復旧できる
- 遷移表の全行が自動試験で通る

## ステップ 4: セットアップ機能（地図・地点・エリア）

- [ ] **4-1 地図作成**: slam_toolbox による地図作成（StartMapping / WatchMappingPreview / SaveMapping / DiscardMapping）と、AMCL との切り替え
- [ ] **4-2 地図の編集と版の管理**: ノイズの除去、地図の上書き・複製・巻き戻し、再スキャン後の地点の再確認
- [ ] **4-3 エリア**: 立入禁止・速度制限エリアを多角形で持ち、Nav2 のコストマップフィルタ用のマスク画像を生成する
- [ ] **4-4 地点の登録**: 地図上のクリックとティーチング（現在位置の記録）、移動モードと到達許容誤差
- [ ] **4-5 UI**: ① 地図の登録、② 目標地点の登録、③ テスト、⑥ 地図・地点の更新

**確認できること**
- 新しい環境で、地図作成から地点登録、巡回の実行まで UI だけでできる
